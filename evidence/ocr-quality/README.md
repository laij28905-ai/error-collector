# 手写 OCR 失败与手机核对页修复 · 2026-10-30

## 定位

用户截图显示手写公式、下标和二维数值表格，识别结果大量乱码。截图不是原始输入图，没有该次 Tesseract confidence/words 数据，因此不能给出该次准确率或保证新阈值一定能拦截此图。

Tesseract 官方 FAQ 明确说明引擎面向印刷体，手写效果不佳：https://tesseract-ocr.github.io/tessdoc/FAQ#can-i-use-tesseract-for-handwriting-recognition 。符号后处理无法恢复已经错读的内容或表格结构。

代码问题：此前 runOcr 把任何非空文本送到保存页；runTesseractOcr 未使用引擎质量分数，仍继续公式局部重识别；“校正后”的标题容易使人误以为已修正题意；手机默认展开的两栏长文本位于编辑框前，sticky 保存区可覆盖滚动文本。

## 本轮变更

- 用引擎总体分数低于 60、至少 5 个有效词且过半词分数低于 50、空输出作为低质量提示依据。属于启发式提醒，不是准确率、手写分类器或语义正确性判断；高分同样可能识错。
- 低质量结果不再进行最多 8 次公式 ROI 重试；非空低质量草稿需人工核对勾选后才保存，编辑/采纳候选后重新核对。
- 核对页提供“清除识别文字，仅保留图片”，保留已选学科和补充字段；清除乱码后图片可独立保存，支持原有连续选题。
- 空 OCR 结果直接进入原图保存流程，不再仅跳转手动输入。
- 编辑框提前，对比默认折叠，手机单列且限制预览高度；标题改为“当前编辑”，标记数量不代表全部错误数；保存区回归正常文档流，避免覆盖正文。
- 入口标注“离线识别（印刷体）”，说明手写、公式表格的限制；AI 识图清除上一轮 OCR 质量状态，不沿用错误的低分判断。

## 验证证据与边界

- `unit.txt`：原有数据、公式规范化、API 检查，以及低分/空输出/词分数判断断言通过。
- `acceptance.txt`：完整原有浏览器验收，新增同类型的 OCR 失败处理断言；16 项 passed，1 项合成公式识别仅 recorded，未宣称公式准确率通过。
- `results.json`：结构化结果。
- `mobile-editor.png`：375×812 Edge 模拟视口，使用合成印刷图与人工注入的低质量 OCR 文本，不是用户题图识别效果。截图不含用户提供的人脸或真实手写资料。
- 低质量场景注入 confidence=18，核对：跳过 ROI、不确认不能写入、修改文字撤销确认、折叠对比、手机单列、保存区非悬浮、只存图片成功且 ocrRaw 为空。空结果也保留原图与表单。
- 原有真正杀服务器后冷启动 OCR/保存、导入取消、遮罩异常、复习防连点、同步合并、AI 模拟响应、超时、缓存升级、触摸裁剪与存储降级验收通过。

## 还需要什么

准确转写这张手写材料尚未解决。需原始照片而非应用界面截图，才可重复评估实际输入；联网方案需要用户在自己手机中配置可用的视觉模型 Key，并用原图逐项核对转写结果，不要把 Key 发到聊天或仓库。严格离线方案需要专门手写数学/表格识别能力、匹配的浏览器推理运行环境和真实手机性能测试，当前轻量 Tesseract 包不具备此能力。

截图右上角的视频悬浮窗来自应用页面外的覆盖层，其遮挡不由 PWA 控制，需在所属应用/系统中收起。未对用户当前手机进行远程操作，也未将用户截图发送到任何视觉 API。
