## 1. 目标与范围

目标体验：拍一页试卷 → 必要时扶正 → 框选并保存多道错题 → 离线给出可修改的科目与知识点建议 → 联网时在应用内理解题目、练习变式 → 按真实作答表现复习。

保留原生 HTML/CSS/JS、IndexedDB、Service Worker。不开后端、不换框架、不新增 npm 依赖、不修改 vendor 下的现有二进制。原题图是记录依据；OCR 文字、规则分类和 AI 结果都允许校正，识别失败不阻止保存。

比赛前必交：现有手机流程核实、离线分类建议、至少一家真实视觉 API 的完整演示验证。扫描校正和复习改进分独立版本交付，没过验收就不进入演示版。最迟在实际演示前 24 小时冻结功能；剩余时间只修阻断问题、整理证据与彩排。

## 4. 执行顺序与交付门槛

### 第 0 轮：确认手机基线与回滚点（1–2 小时）

工作：导出现有错题备份，固定当前部署版本；在真实手机完成相册选图、框选、连续保存三题、重新编辑、复习；确认页面更新不丢本地数据。建立同一套真实题图和参考标签，避免后续只挑识别成功的图片。

验收：三条记录对应三个不同选区，图中文字和几何图可放大查看；保存失败保留草稿；按钮不被导航或键盘遮挡；截图记录手机型号、系统、浏览器和网站版本。

手机无法获得时，标明“浏览器通过、真机未验证”，不得替代真机结论。现有阻断缺陷优先于后续功能。

### 第 1 轮：离线分类建议（3–5 小时，必做）

用户体验：保存页出现“建议：数学 / 数列”，展示简短依据，如“题干包含等比数列”；可以采纳、改选或跳过。只存图片也能立即保存。OCR 有误、信息不足、候选冲突时显示“待分类”，不强行归入数学。

实现：

1. 从现有 KNOWLEDGE_MAP 建立稳定知识点 ID、名称、别名、词组规则和反例，第一批只针对数学、物理、化学、生物；其他学科保留手选。
2. 采用规则评分和多证据匹配，不将内部得分显示为未经校准的“置信度百分比”。例如不能因为题干出现“芯片”就判为物理；“等比数列”是更直接的数学依据。
3. 一次建议最多给出两个知识点。记录建议来源 `rule/ai/manual`、规则版本与用户最终选择。用户手动选择后，后续识别不自动覆盖。
4. 图片记录和 OCR/分类分开保存；失败时原图不丢失。新增字段向后兼容；导入、导出、同步校验同时补齐，不只改显示层。

拟改文件：新增 `js/classify.js`；小范围修改 `js/app.js` 的 guessSubject/openSaveModal/fillTopicSelect/submitSaveForm、`js/reliability.js` 校验、`app.html` 脚本引入、`sw.js` 壳缓存。

验收：用预先固定的 20 道真实题目进行人工标注，其中数学 10、物理 4、化学 3、生物 3。以本地 OCR 输出进入分类，分别报告“给出建议的覆盖率”及“给出的科目与主知识点同时正确的比例”。目标覆盖率 ≥60%、建议正确率 ≥85%；无建议算覆盖失败，不藏进分母外；另记录清晰人工文本结果以区分 OCR 与规则问题。该样本仅用于演示验证，不外推总体准确率。未达标则缩小自动建议范围、保留手选并公布结果。

### 第 2 轮：斜拍试卷扶正（4–6 小时，有条件交付）

先做限时 90 分钟可行性验证：对用户已有三张试卷图以及两张真实斜拍照片，检查 Scancat 校正函数能否独立运行、内存是否合理。截图黑边、整页纸张与单题边界分开处理；纸张检测不等于自动找题号。

实现顺序：

1. “校正整页”作为独立可跳过入口，先让用户拖四角，显示校正预览；接受后返回已有矩形框选。避免把矩形裁剪手柄同时变成四角校正手柄。
2. 保留未处理原图；拒绝自交、共线和面积过小的四边形，限制输出尺寸。校正使用逆映射与插值，在 Worker 执行，支持取消、超时和失败退回原图。
3. 手动四角通过后才启用“自动找边”候选。检测不可靠时保留手动模式，不自动裁掉内容。
4. 图像增强只给可撤销的轻量选项，不默认删除批注、不承诺去阴影或手写清除。自动拍照、曲面书页展平和自动分题均不在本轮。

拟改文件：新增来源明确的 `js/scan-core.js`、`js/scan-worker.js` 和适配入口；小范围连接 `js/crop-enhance.js`、`js/app.js`、`sw.js`；新增 `THIRD_PARTY_NOTICES.md`。不复制整套仓库，不改 vendor 二进制。

验收：5 张固定真实照片逐张对照，文字、选项、图形不被误裁，不出现镜像或空白；取消/失败后原图一致。记录实际手机每张耗时，目标最长边 2400 像素的单次校正 ≤3 秒，超时 8 秒退出并保留原图。未满足时保持原矩形框选，不把未经验证的自动校正放进默认演示流程。

### 第 3 轮：联网结果结构化、可核对（3–5 小时，必做）

用户体验：主动点击 AI 后，在同一个应用里核对题干、条件、考点和解题步骤；看不清的位置明确标出。生成一道同考点变式，答案折叠显示，做完可以记录结果。

实现：沿用现有 API 客户端与 15 秒超时，不新建另一套模型配置；统一结构化字段 `stem/conditions/subjectId/topicIds/solution/uncertainParts/variants`，校验类型与长度，过滤不存在的知识点 ID。AI 不确定或 JSON 不合法时不写入半成品、不覆盖原题。没有学生过程时只给“常见易错点”，不认定个人错因。离线继续保存和规则整理，规则生成的内容不标为 AI。

变式先做一道，并保存题干、答案、说明、模型来源、用户作答和结果；“完成勾选”不直接变成“已掌握”。历史 similar 字符串数组仍可展示，新旧格式都能备份恢复。若该部分不能按时通过，保留现有变式展示并明确未做自动判定。

拟改文件：`js/ai-client.js`、`js/app.js` 的 callAi/复盘详情/变式区域、`js/reliability.js` 结果与备份校验；复用现有 UI，不新增一级页面。

验收：用户在自己的设备中填写 Key，不发到聊天、不写入证据；选择一家用户可访问的视觉服务，用上述第 16 题完成识图→校对→讲解→一道变式→记录结果。人工检查条件是否忠于原图，不能只以 HTTP 200 为成功。断网、超时和返回格式错误时保留原图、表单并关闭遮罩；请求只在用户明确触发时发送。没有可用 Key 时记“真实服务未验证”，不以模拟响应顶替。

### 第 4 轮：复习行为与间隔（2–4 小时，排在前述必做项之后）

先记录“未做出/提示后做出/独立做出/轻松做出”及时间；跳过不评分，查看答案不计正确。追加不可重复写入的复习事件，显示下次复习日期及简短原因。再将间隔计算抽成小型纯 JS 调度器，借鉴 SM-2，不引入完整 FSRS。算法版本和事件 ID 随备份保留。

不由累计点击次数直接宣布掌握，不把评分概率包装成学习效果证据。旧题保持原状态和 nextReviewAt，首次新评分再进入新调度，不批量改写历史。复习日志采用事件 ID 去重合并，不能单用整条记录 updatedAt 丢掉另一设备的作答。

拟改文件：新增 `js/review-schedule.js`；修改 `js/app.js` rateReview/展示、`js/reliability.js` 导入合并；必要时明确兼容字段，不做不可逆迁移。

验收：相同输入得到相同日期；答错比独立做对更早复习；重复点击只产生一个事件；跳过不改计划；旧备份可以导入；双份日志合并不丢失、不重复。沿用现有 unit.cjs 与 acceptance.cjs 验证方式，不新建测试框架。

## 5. 时间安排与删减顺序

完整计划约 16–26 小时有效工时，包括最终验收 3–4 小时；时间取决于真实设备、题图质量与 API 可用性。

- 第一天：第 0 轮 + 第 1 轮；剩余时间只做扫描可行性验证。
- 第二天：通过可行性验证才实施第 2 轮；优先为第 3 轮真实 API 留足时间。
- 第三天：先完成第 3 轮；有余量才做第 4 轮；最后冻结、回归、彩排。
- 若只剩一天：仅做第 0、1 轮和现有 API 真机验证，不启动自动找边、新调度器或新变式结构。
- 若超时：依次取消图像增强、自动找边、复习调度升级、变式自动判定；保住原图保存、手动框选、可修改分类和已验证的联网讲解。

## 6. 统一交付与验收

每轮一个独立可回滚提交，保持同一仓库与部署分支。部署前完成相应验证；发布递增壳缓存版本，不清 OCR 缓存、不清用户错题，更新由用户保存编辑内容后接受。

复用现有 `node tests/unit.cjs`、`node tests/acceptance.cjs`，只对新增逻辑补充有意义的断言。纯样式只核对截图与交互，不反复跑无关大套件。真实设备操作、真实题图评价和断网方法沿用已约定验收，不再增加测试平台。

最终演示证据：

1. 新浏览器 profile 联网准备 → 退出 → `taskkill.exe /PID <本轮服务PID> /T /F` → HTTP 探测 ECONNREFUSED → 冷启动 → 识别→保存；保留命令原文、PID 和完整日志。CDP 仅用于触摸输入，不能充当断网证明。
2. 真机首次联网准备，随后断开 Wi-Fi/移动数据，重新打开已安装应用，完成框选保存与复习，记录真实设备结果。
3. 首页/识别后/复习页的 375×812 和真机截图；弹窗滚动、键盘遮挡、裁剪手感记录。
4. 固定 5 张真实题图：每张需修改字符数、修改位置数、耗时、失败原因，公开平均值与最差值。原目标平均 ≤2 处、≤30 秒，未达到就明确记录；手动挑图或替换成合成文字不算达标。
5. 导入取消不改条数；5 次含异常复盘不锁死；5 页切换 3 轮无非预期错误；备份含新增字段且不含 Key。
6. 每轮交付版本 hash、变更文件、截图/日志路径、线上版本核对及未解决项，说明哪些是模拟测试、哪些是真实服务或真机验证。

## 7. 本阶段明确不做

不重做班级/题库/家长管理；不接 MCP 或云端长期记忆；不迁移 Next.js/React/Python；不做大规模向量库；不声称自动判断所有题目或数学公式全对；不追求扫描全能王的全套功能；不把动画或更多模型入口作为竞赛亮点。
